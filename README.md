**微信公众号及网页内容采集系统 —— 总体设计文档（修订版）**

---

## 一、设计目标

构建一套以你的**Windows 电脑为核心处理节点**（后期平滑迁移至树莓派），覆盖**iPhone、PC 浏览器**两端输入的内容采集系统。  
核心能力：你在任何设备上看到有价值的文章（微信公众号、CSDN、知乎、技术博客等），**三秒内完成 URL 收录**，由电脑在后台自动下载原文、图片，并按原排版顺序保存为本地文件。

**安卓端预留扩展接口**，当前阶段不开发，但架构上确保后续可无缝接入。

---

## 二、总体架构（四层模型）

```
┌─────────────────────────────────────────────────────────────┐
│                    采集层（各端设备）                          │
│  iPhone微信              PC浏览器（CSDN/知乎/任意网页）        │
│      │                        │                              │
│      └────────────────────────┘                            │
│                     ↓                                        │
│              统一投递接口                                     │
│         （预留：Android HTTP Shortcuts 接入点）               │
├─────────────────────────────────────────────────────────────┤
│                    传输层（统一收集池）                        │
│              本地接收服务（运行在你的Windows电脑）              │
│         （后期迁移：树莓派 4B，通过 Tailscale 支持外网访问）    │
│                     ↓                                        │
│              URL 待处理队列（文本文件/SQLite）                │
├─────────────────────────────────────────────────────────────┤
│                    处理层（电脑/树莓派后台）                    │
│         调度器 → 分类器 → 下载器 → 解析器 → 打包器            │
│                     ↓                                        │
│              本地文件系统（Markdown + 图片文件夹）              │
├─────────────────────────────────────────────────────────────┤
│                    存储层（本地持久化）                        │
│         按日期/来源分类的文件夹 + 索引清单（SQLite）           │
└─────────────────────────────────────────────────────────────┘
```

## 三、分层详细设计

### 第一层：采集层（设备端）

| 设备 | 采集方式 | 用户操作 | 技术依赖 |
|:---|:---|:---|:---|
| **iPhone** | iOS 快捷指令 | 微信文章页 → `...` → 分享 → 选「收文章」 | iOS 系统原生，无需额外 App |
| **PC 浏览器** | 浏览器书签按钮 | 看网页时点击书签栏「收录」按钮 | 无需安装插件，一次配置永久可用 |
| Android (预留)| HTTP Shortcuts App | 微信文章页 → `...` → 分享 → 选快捷方式 | 当前不开发，架构预留 POST 接口 |

**设计原则**：各端只做一件事——**把当前网页 URL 发送出去**，不做任何本地存储或解析。

---

### 第二层：传输层（统一收集池）

**当前阶段**：以 **电脑本地服务为主通道**，**邮件/飞书为备用容灾**。

| 场景 | 通道                              | 说明 |
|:---|:--------------------------------|:---|
| iPhone 与电脑同 WiFi | 本地服务 `http://电脑IP:5080/collect` | 主通道，实时、无延迟 |
| iPhone 在外（不同 WiFi/4G） | 备用通道：邮件发给自己 / 飞书机器人             | 延迟处理，电脑开机后补录 |
| PC 浏览器 | 直接访问本地服务或书签脚本 POST              | 与 iPhone 共用同一接口 |

**树莓派迁移规划**：

| 阶段 | 部署方式 | 网络方案 |
|:---|:---|:---|
| **第一阶段（当前）** | Windows 电脑运行 | 局域网直连，iPhone 需同 WiFi |
| **第二阶段（后期）** | 树莓派 4B 运行 | Tailscale 虚拟组网，iPhone 在外网也能直接访问树莓派，无需备用通道 |

**设计决策**：
- 本地服务接口保持简单：`POST /collect`，JSON Body `{"url": "..."}`
- 备用通道降级逻辑由 iPhone 快捷指令处理（请求超时自动切换）
- 树莓派迁移时，只需改快捷指令里的 IP 地址，其他不变

---

### 第三层：处理层（电脑/树莓派后台）

常驻后台运行，Python 编写。

| 模块 | 职责 | 说明 |
|:---|:---|:---|
| **调度器** | 定时扫描收集池，发现新 URL 就触发任务 | 每 5 分钟检查一次 inbox 文件；后期可改为实时监听 |
| **分类器** | 判断 URL 来源类型 | `mp.weixin.qq.com` → 微信类；`blog.csdn.net` → 技术博客类；未知 → 通用类 |
| **下载器** | 用浏览器自动化打开网页，获取完整渲染后的 HTML | 微信公众号必须走 Playwright；普通博客可简化 |
| **解析器** | 按来源类型提取正文、标题、图片、发布时间 | 微信用 `#js_content` 规则；CSDN 用 `.blog-content-box` 规则；未知网站用通用算法 |
| **打包器** | 按原顺序组装为 Markdown 文件，图片重命名并放入子文件夹 | 输出格式统一，便于后续阅读或建立知识库 |

**关键设计**：解析器支持**插件式扩展**。新增网站只需新增一条解析规则，不影响已有功能。

---

### 第四层：存储层（本地文件系统）

**目录结构规范**：

```
采集库/
├── inbox/
│   └── urls_pending.txt          # 待处理 URL 队列（传输层写入，处理层读取）
├── output/
│   ├── weixin/                   # 微信公众号文章
│   │   ├── 2026-06-08/
│   │   │   ├── 文章标题A/
│   │   │   │   ├── article.md
│   │   │   │   └── images/
│   │   │   │       ├── 001.jpg
│   │   │   │       └── 002.jpg
│   │   │   └── 文章标题B/
│   │   └── 2026-06-09/
│   ├── csdn/                     # CSDN 文章
│   ├── zhihu/                    # 知乎文章（预留）
│   └── unknown/                  # 未识别来源
└── index.db                      # SQLite 索引：URL、标题、保存时间、本地路径、是否已读
```

## 四、数据流标准流程

```
1. 用户 iPhone 看微信文章 → 点击分享 → 快捷指令
2. 快捷指令尝试 POST 到电脑本地服务（192.168.x.x:5000/collect）
   ├─ 成功 → URL 写入 inbox/urls_pending.txt
   └─ 失败（超时/电脑离线）→ 自动降级：发送邮件/飞书给自己
3. 调度器（每5分钟）扫描 inbox 文件
4. 分类器识别为「微信公众号」→ 调用微信下载器
5. 下载器启动 Playwright 浏览器 → 打开文章 → 等待渲染 → 提取 HTML
6. 解析器提取标题、正文段落、图片地址（按 DOM 顺序）
7. 图片下载（带微信 Referer 防盗链头）→ 存入 images/
8. 打包器生成 Markdown → 存入 output/weixin/日期/标题/
9. SQLite 索引更新状态为「已完成」
10. 用户后续在电脑上直接打开 Markdown 阅读
```

## 五、非功能性需求（可靠性设计）

| 问题 | 设计对策 |
|:---|:---|
| **电脑关机时手机发送 URL** | 快捷指令捕获超时后，自动降级发送到备用通道（邮件/飞书），电脑开机后从备用通道补录 |
| **同一文章重复收录** | SQLite 索引以 URL 为主键，重复 URL 自动去重，不重复下载 |
| **文章已被删除或链接失效** | 下载器捕获异常后，在索引中标记为「失败」，保留 URL 便于手动核查 |
| **图片下载不全** | 打包器最后校验：Markdown 中引用的图片数 vs 实际下载数，不匹配则标记「图片缺失」 |
| **微信反爬升级** | 下载器模块独立封装，如果微信加强检测，只改这一小块，不动整体架构 |
| **树莓派迁移** | 所有代码与配置与平台无关，只需在新设备重新安装 Python + Playwright，复制项目文件夹即可运行 |

## 六、关键技术选型

| 层级 | 技术 | 安装方式 | 理由 |
|:---|:---|:---|:---|
| 本地服务 | Python + Flask | `pip install flask` | 你熟悉 Python，轻量 |
| 浏览器自动化 | Playwright | `pip install playwright` + `playwright install` | 比 Selenium 更难被微信检测，支持移动端 UA 伪装 |
| 解析与提取 | BeautifulSoup / Readability | `pip install beautifulsoup4 lxml` | 微信用 BS4 精确提取；未知网站用 Readability 通用提取 |
| 数据存储 | SQLite | Python 内置 | 你熟悉 SQLite，无需额外安装 |
| 后期组网（树莓派） | Tailscale | 官网下载安装 | 免费版够用，iPhone 在外网也能访问家里树莓派 |

## 七、边界与限制

1. **电脑/树莓派必须作为处理中心**：下载和解析必须在后端完成，手机/浏览器只负责传 URL。
2. **当前阶段 iPhone 需同 WiFi 才能实时投递**：另一半时间走备用通道（有延迟）。
3. **微信公众号必须走浏览器渲染**：不能简化为纯 HTTP 下载。
4. **新网站需适配解析规则**：每新增一类网站，需要新增对应的解析器规则。
5. **图片防盗链是强约束**：微信公众号图片必须带特定请求头。

## 十、 调用方法

### 项目文件结构

```
TailoredArticle/
├── server.py                     # 主服务
├── collector.py                  # 采集方法
├── tools.py                      # 工具性方法，如判断网页正文何时结尾
├── analyze.py                    # 智能分析，分类打标签、提取摘要、关键词等
└── web                           # 网络浏览采集内容
```

### 启动方法

```commandline
> python .\analyze.py --help

usage: analyze.py [-h] [-m {all,one,loop}] [-id [ID]] [-s SLEEP]
optional arguments:
  -h, --help            show this help message and exit
  -m {all,one,loop}, --mode {all,one,loop}
                        命令：all=分析所有未分析文章，one=分析指定ID文章, loop=定时循环分析所有未分析文章
  -id [ID]              文章ID（仅当mode=one时有效）
  -s SLEEP, --sleep SLEEP
                        循环分析间隔秒数（仅当mode=loop时有效）
                        
> python .\ananalyze.py -m one -id 1
> python .\ananalyze.py -m all
> python .\analyze.py -m loop -s 3600
```
